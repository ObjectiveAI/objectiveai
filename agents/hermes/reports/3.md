# Report 3 — streaming: Hermes speaks ACP, and that is our wire

From the pinned source (`sources/hermes-agent`, `4209d371`,
v0.20.6). The question was whether Hermes can stream structured
output the way Claude Code's stream-json does — because `hermes -z`
prints final text only, and a chunk stream cannot be carved from
that. The answer is better than a flag: **Hermes ships a first-class
ACP (Agent Client Protocol) adapter — an async JSON-RPC stdio
server — and it streams everything our chunk vocabulary wants.**

## The surface

`hermes acp` (also `hermes-acp`, `python -m acp_adapter`;
`acp_adapter/entry.py`). Stdout is RESERVED for JSON-RPC transport;
logs go to stderr — the same stdout discipline cc's stream-json
gave us, stated in the docs and defended all over `hermes_cli` ("
`hermes acp` speaks JSON-RPC on stdout"). Boot loads
`~/.hermes/.env` and reuses the runtime provider/credential
resolver — no separate ACP auth store
(`website/docs/developer-guide/acp-internals.md`).

The protocol library is pinned by Hermes itself:
`agent-client-protocol==0.9.0` (pyproject extra `acp`), run with
`use_unstable_protocol=True` — version-sensitive, so OUR image pins
Hermes and inherits an exact ACP dialect, the same
pinned-image-closes-the-union argument cc's strict parser makes.

## What streams (the event bridge, `acp_adapter/events.py` + `server.py`)

Per prompt turn, `session_update` notifications carry:

- **`agent_message_text`** chunks — assistant text, streamed.
- **`agent_thought_text`** chunks — REASONING, streamed (bridged
  from Hermes's step callback).
- **`ToolCallStart` / tool-call updates** — tool id, kind, progress,
  completion, with FIFO id tracking for duplicate same-name calls
  (`events.py:128-165`).
- **`plan`** updates — Hermes's task list (Zed renders it; we could
  map to notifications or drop).
- **`usage_update`** — NATIVE context-window occupancy (the very
  thing Claude Code never puts on its wire — Hermes does:
  `server.py:999-1046`).
- The prompt RESPONSE closes the turn with a `stop_reason`
  (`cancelled` among its values).

Sessions: `new / load / resume / fork / list / cancel`
(`server.py`, `SessionManager` in `session.py`). Loading REPLAYS
history as the same update kinds — thought chunks and reconstructed
tool-call start/completion (`server.py:1502-1540`) — so a resumed
run narrates its past on the same wire.

Permission prompts arrive AS ACP permission requests
(`permissions.py`: `allow_once`/`allow_always`/deny; timeouts deny).
Our harness answers them — the `--yolo` analog is an auto-approve
policy in OUR client, not a flag we hope reaches the subprocess.

## What this maps to (the container sketch)

- `agent_message_text` → `AssistantTextContent`;
  `agent_thought_text` → `AssistantReasoning`; tool-call
  start/update → `AssistantToolCall` / `ToolResponse`.
- One ACP session per container run; one `prompt()` per turn — WE
  drive the loop, which makes the queue story OPENROUTER's, not
  cc's: a harness-owned queue delivered between prompt calls (the
  two seams, take_or_close, the whole proven machinery), because
  ACP has no mid-turn enqueue. `cancel(session_id)` exists but is
  turn-abort — the 'now' priority we deliberately never use.
- The spawn shape is cc's: subprocess, stdin/stdout piped, a typed
  message layer — JSON-RPC framing instead of NDJSON records.
- MCP: Hermes tool calls run HERMES's own tools. Whether the
  caller's MCP servers (our 8081 proxy) can be injected as Hermes
  toolsets/MCP config is the next research item — `AIAgent(...,
  enabled_toolsets=["hermes-acp"])` suggests toolset selection is
  programmable at session construction.

## Open questions for report 4

1. **Billing.** `usage_update` is context occupancy, not spend. The
   `--usage-file` bill (cost, tokens, session_id) belongs to the
   plain CLI path — where the ACP path's equivalent lives (the
   SQLite store? a session table?) decides our `UsageChunk` source.
2. **Continuation.** Hermes persists sessions in SQLite — BINARY,
   which cc's text-only continuation token (`content: String`,
   UTF-8-skips-binary) cannot carry. Either the hermes token
   carries bytes (its own continuation format — tokens are
   per-container anyway), or we ride `hermes sessions export`
   (JSONL) — IF an import path exists. ACP `load/resume` by
   session id says on-disk state is the resume key, like cc.
3. **MCP injection** — caller toolsets into the ACP session.
4. **Skills/mounts** — where Hermes discovers skills on disk (the
   mounts' target paths), and whether `-s` selection has an ACP
   session equivalent.

## The verdict

Drive Hermes through `hermes acp` over stdio. It is stream-json's
equal or better on every axis we care about — typed streaming
(text, reasoning, tool lifecycle), session resume with history
replay, cancellation, native context usage — and it is a PROTOCOL
with a pinned version rather than an output format we reverse. The
`-z`/`--oneshot` path stays what it is: a fallback we should not
need.
