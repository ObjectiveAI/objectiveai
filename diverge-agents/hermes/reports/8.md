# Report 8 — yuanbao in the container: coupled to a platform we don't run

From the pinned source (`sources/hermes-agent`, v0.20.6).

## What it is

Five `yb_*` tools for Tencent Yuanbao group/DM operations. Their
gate (`tools/yuanbao_tools.py:420-428`) passes only when the
session's platform IS yuanbao, or a LIVE Yuanbao gateway adapter
exists — the singleton a running gateway platform creates and holds
a persistent WebSocket through (`gateway/platforms/yuanbao.py:
5313-5315`).

## Why credentials are not enough

The `YUANBAO_APP_ID`/`app_secret`/`bot_id`/`ws_url` credentials
only let the ADAPTER fetch its sign-token and connect
(`yuanbao.py:399-551`); every tool body reads the connected adapter
and answers `{"success": false, "error": "Yuanbao adapter is not
connected"}` otherwise (`yuanbao_tools.py:60-61`). Our container
runs the gateway with ONLY the api_server platform — no Yuanbao
platform, no adapter, no WebSocket.

## Verdict and recommendation

Dead here by construction, and gracefully so (hidden by the gate;
polite errors if forced). Enabling the Yuanbao PLATFORM in our
container would mean the agent living in someone's chat groups
beside the protocol run — out of scope by any reading.
`Toolsets.yuanbao` should leave the vocabulary.
