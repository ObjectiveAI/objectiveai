# Report 6 — stt in the container: not a tool at all

From the pinned source (`sources/hermes-agent`, v0.20.6).

## What it actually is

`stt` is a CONFIG-ONLY entry — one of the `_CONFIG_ONLY_TOOLSETS`
(`hermes_cli/tools_config.py:158-164`): it appears in the `hermes
tools` wizard so a user can configure transcription providers, but
it ships ZERO tool schemas. `tools/transcription_tools.py` contains
no registry registration; the model can never call it.

## Where transcription really happens

Every call site is a non-agent INGEST path: inbound voice messages
on gateway messaging platforms (`gateway/run.py:25808-25835`,
Discord at `plugins/platforms/discord/adapter.py:4948`), local mic
capture in voice mode (`tools/voice_mode.py:1415-1476`), and the
dashboard's recording upload. The API server explicitly has no
audio surface: its capability flags say `"audio_api": False,
"realtime_voice": False` (`gateway/platforms/api_server.py:
3365-3366`) — and our protocol's prompts are text besides.

## Verdict and recommendation

Not questionable — inapplicable. There is nothing to enable or
disable at the agent level; the switch would toggle a checklist
row, not a capability. `Toolsets.stt` should leave the vocabulary:
a switch that cannot change what the model can do is protocol
noise.
