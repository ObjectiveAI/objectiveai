# Report 9 — context_engine in the container: an empty socket

From the pinned source (`sources/hermes-agent`, v0.20.6).

## What it is

A toolset declared with zero tools (`toolsets.py:207-211`) whose
contents are injected at runtime from the active context engine's
`get_tool_schemas()` (`agent/agent_init.py:2898-2933`). The
BUILT-IN engine — `ContextCompressor` — inherits the ABC's default,
which returns `[]` (`agent/context_engine.py:413-419`); the
docstring names the intended filler ("LCM would return schemas for
lcm_grep, lcm_describe, lcm_expand here"), and the
`plugins/context_engine/` directory ships only an `__init__.py` —
no engines in-repo.

## Behavior

Enabling it is a harmless no-op: nothing appears in the schema, and
a malformed plugin's schemas would be skipped with a warning rather
than poisoning the request (`agent_init.py:2915-2925`).

## Verdict and recommendation

Doable in the trivial sense (nothing breaks) and useless in the
real one (nothing exists to enable) — stock Hermes cannot populate
it, and our container runs stock Hermes. `Toolsets.context_engine`
should leave the vocabulary until an engine plugin is something our
image ships, at which point it becomes an ordinary switch again.
