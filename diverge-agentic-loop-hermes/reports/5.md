# Report 5 — cronjob in the container: live where it shouldn't be

From the pinned source (`sources/hermes-agent`, v0.20.6).

## What it is

Agent-managed scheduled jobs: persisted to
`~/.hermes/cron/jobs.json` (`cron/jobs.py:80-85`; SQLite only for
the attempt ledger, `cron/executions.py:33`), executed by a
60-second tick loop that runs on a background thread INSIDE THE
GATEWAY PROCESS — the only production start site is
`gateway/run.py:32172-32190` (`cron/scheduler.py:1-8`,
`cron/scheduler_provider.py:548-600`).

## Why our architecture makes this LIVE, not hidden

The tool's gate (`tools/cronjob_tools.py:2033-2052`) requires one
of `HERMES_INTERACTIVE` / `HERMES_GATEWAY_SESSION` /
`HERMES_EXEC_ASK`. A one-shot `hermes -z` run sets none — hidden.
**But our container runs the GATEWAY** (the api_server wire), and
the gateway sets `HERMES_EXEC_ASK=1` (`gateway/run.py:31593`) and
starts the scheduler. So in our container, unlike the one-shot
picture: the tool is OFFERED by default, jobs persist, and the
ticker actually fires them.

## Why that is wrong for a one-run container

A cron job firing means a NEW agent run starting inside the
container — outside the protocol entirely: no request asked for it,
no stream carries it, its usage bills nobody, and it races the one
run the container exists for. A job scheduled beyond the container's
life dies silently with it, which at least is only a broken promise
to the model. Both halves are wrong; the first is dangerous.

## Verdict and recommendation

Doable in the literal sense — which is exactly the problem. The
harness must force it OFF (`platform_toolsets.api_server` without
`cronjob`, or `agent.disabled_toolsets`) regardless of the caller's
switch, and the `Toolsets.cronjob` switch should either leave the
vocabulary or be documented as harness-overridden. Note the tick
loop also costs a background thread and a file lock
(`~/.hermes/cron/.tick.lock`) even with zero jobs — disabling the
toolset does not stop the scheduler, only the model's ability to
feed it, which is sufficient.
