# Report 4 — computer_use in the container: no, and dangerously not

From the pinned source (`sources/hermes-agent`, v0.20.6).

## What it is

`computer_use` drives a real desktop through **cua-driver** — a
third-party Rust binary (trycua/cua) Hermes spawns as an MCP stdio
server over a unix socket (`tools/computer_use/cua_backend.py:1-34`,
spawn at `:823-847`, contract floor cua-driver ≥ 0.20.0 at
`:1177-1188`). It captures the screen and injects events into real
GUI applications.

## Why it cannot work here

A headless container has no display server and no desktop session.
The docs are explicit (`website/docs/user-guide/features/
computer-use.md:428-431`): Linux requires a reachable display —
headless needs `Xvfb :99` running BEFORE the tool can capture — and
the prerequisite table adds **AT-SPI** (the accessibility tree),
present on GNOME/KDE/Xfce and absent in a bare Debian container.
Even with both, there would be no GUI application to drive. Their
own docs point away (`:435-436`): "the `browser` toolset uses a
real headless Chromium and is the right answer for web-only tasks."

Nothing ships the driver either: their Dockerfile has zero
cua-driver/Xvfb references; installation is an out-of-band setup
step, Linux marked alpha (`hermes_cli/tools_config.py:980-1040`).

## The failure mode — the reason this report exists

The availability check (`tools/computer_use/tool.py:1678-1691`)
verifies ONLY platform + binary-resolves. **It never checks
`DISPLAY`.** So:

- driver absent → tool silently hidden (fine);
- driver installed, no display → the tool APPEARS in the model's
  schema and fails at capture time — empty window discovery, with
  the diagnosis buried in a string: "no DISPLAY is set —
  X11/XWayland is not reachable from this process"
  (`cua_backend.py:465-466`). A visible tool that can never work is
  the worst shape a capability can take: the model will keep
  reaching for it.

## Verdict and recommendation

Not doable, and not worth making doable (Xvfb + AT-SPI + a synthetic
desktop to drive nothing). The container must never install
cua-driver, and the `computer_use` switch on the agent's `Toolsets`
should either leave the vocabulary or be documented as
force-disabled by the harness regardless of the caller's value.
