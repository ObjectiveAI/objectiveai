Channel tag `4`. The one exchange of the five that is not answered
once: the channel remains open, and each response carries one server
notification from the client's MCP servers — tools changed, resources
changed, a resource updated, a log message — as defined by the [Model Context Protocol specification](https://modelcontextprotocol.io/specification/2025-11-25).

The exchange mirrors MCP's own notification stream, which a client
opens with a bare `GET` and no body; accordingly the
[request](/endpoints/agentic-loop-run/channels/mcp-notifications/request/)
carries nothing, and the
[responses](/endpoints/agentic-loop-run/channels/mcp-notifications/response/)
flow until the channel's finish.
