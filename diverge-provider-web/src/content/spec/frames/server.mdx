A server sends six frame types.

- **Type `0` — authorization.** The scope and channel fields are zero
  and carry no meaning. The payload is a credential. Sent only when
  the server is the connection's initiator, only as the connection's
  first frame — see [Authorization](/frames/authorization/).
- **Type `2` — response.** One piece of the answer to a
  [scope](/frames/scopes/)'s request. The scope field names the scope;
  the channel field is zero. The payload is the piece.
- **Type `3` — response finish.** Ends a scope. The scope field names
  it; the channel field is zero; there is no payload. It is the only
  way a scope ends.
- **Type `4` — channel request.** Opens a
  [channel](/frames/channels/) within an existing scope. The scope
  field names that scope; the channel field carries a nonzero number
  of the server's choosing. The payload is the channel's one request.
- **Type `5` — channel response.** Answers a channel *the client
  opened*, quoting the client's channel number. The payload is one
  piece of the answer.
- **Type `6` — channel response finish.** Ends a channel the client
  opened, quoting its number. It carries no payload, and it is the
  only way such a channel ends.

The Rust SDK models these frames as the following enumeration, one
variant per type. The definitions above are normative; the code is an
illustration.

```rust
pub enum ServerFrame<'a> {
    /// Type 0.
    Auth { payload: &'a [u8] },
    /// Type 2.
    Response { scope: u32, payload: &'a [u8] },
    /// Type 3.
    ResponseFinish { scope: u32 },
    /// Type 4.
    ChannelRequest { scope: u32, channel: u32, payload: &'a [u8] },
    /// Type 5.
    ChannelResponse { scope: u32, channel: u32, payload: &'a [u8] },
    /// Type 6.
    ChannelResponseFinish { scope: u32, channel: u32 },
}
```
