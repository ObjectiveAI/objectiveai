---

The client opens the connection, and the connection is the life of
the container: every scope the client opens rides it, in the order
this page states, and nothing survives it.

- **The opening.** The client performs the WebSocket opening handshake
  against port `14979` of the container, at the path `/`. The server
  sends no frame before the client's first frame.
- **One connection.** The server accepts exactly one connection in its
  life. It refuses every later upgrade with HTTP status `409` before
  the upgrade, whether the first connection is open or has ended.
  There is no second connection to a proxy.
- **The first frame.** The first frame the client sends is a request,
  type `1`, opening the begin scope of the container's family:
  [agents::begin](/container-proxy-endpoints/agents-begin/) on an
  agent container, [tools::begin](/container-proxy-endpoints/tools-begin/)
  on a tool container. The client sends it exactly once on the
  connection and before any other request. A second begin is answered
  by exactly one error response and the response finish, and the
  first begin continues.
- **The mounts.** After the begin has been answered, the client opens
  one [fuse::mount](/container-proxy-endpoints/fuse-mount/) scope per
  mount, and opens no other scope until every mount has been
  answered.
- **The rest.** After every mount has been answered, the client opens
  [filesystem::tree](/container-proxy-endpoints/filesystem-tree/),
  [filesystem::read](/container-proxy-endpoints/filesystem-read/) and
  [filesystem::write](/container-proxy-endpoints/filesystem-write/)
  scopes, and channels on the begin scope, in any order and in
  parallel. Neither party opens a channel on the begin scope before
  the server has sent its `Begun` response.
- **The end.** The connection ends when either party closes it, by
  the WebSocket closing handshake or otherwise. When it ends, every
  scope on it is over and every channel with it, without a finish.
  The server re-asks nothing that was in flight, and the client
  re-sends nothing: what was in flight when the connection ended is
  what was in flight when the container ended.
- **The server does not close.** The server closes the connection
  only on a frame of type `0`. It does not close the connection on a
  frame it cannot read, on a request it cannot read, on a scope it
  cannot serve, or after any length of quiet.
