A request the client sends opens a scope, as
[Scopes](/frames/scopes/) provides, for exactly one endpoint of the
[Container Proxy Endpoints](/container-proxy-endpoints/) layer. The
first byte of the request's payload designates the endpoint; the
remainder is the endpoint's request content, in the form the endpoint
defines.

- **The begin, first and once.** The client opens the begin scope of
  the container's family before any other scope, and exactly once on
  the connection. A second begin is answered by exactly one error
  response and the response finish, and the first begin continues.
- **The mounts, each answered before the next step.** After the begin
  has been answered, the client opens one
  [fuse::mount](/container-proxy-endpoints/fuse-mount/) scope per
  mount, and opens no other scope until every mount has been
  answered.
- **The rest, in any order.** After every mount has been answered,
  the client opens [filesystem::tree](/container-proxy-endpoints/filesystem-tree/),
  [filesystem::read](/container-proxy-endpoints/filesystem-read/) and
  [filesystem::write](/container-proxy-endpoints/filesystem-write/)
  scopes, and the channels of the begin scope, in any order and in
  parallel.
- **Channels after `Begun`.** Neither party opens a channel on the
  begin scope before the server has sent its `Begun` response.
- **Unreadable.** A request whose payload the server cannot read — no
  byte, a first byte that designates no endpoint, or content that
  does not conform to the endpoint's form — is answered by a response
  finish that no response precedes. The server sends nothing else for
  it, and the connection continues.
- **Numbering.** The client numbers scopes, and the server learns
  them, as [Scopes](/frames/scopes/) provides. The server opens no
  scope.
