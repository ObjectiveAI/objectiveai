A client opens the scope with a request whose payload is the tag byte
`16` and nothing more. The server sends every image in the client's
Store, one response each, then the word that the listing is whole,
and keeps the scope open: an image that enters the Store is sent as
added, an image whose description is edited as changed, and an image
deleted as removed, for as long as the scope lives. The scope ends at
the client's cancel, at the client's connection ending, or at an
error; the response finish follows, and no frame follows the finish.
A connection holds at most one images::list scope open at a time, as
[One open at a time](/endpoints/#one-open-at-a-time) provides.

- **The request.** The request carries no parameter; the tag is the
  whole of it. [Request](/endpoints/images-list/request/) states its
  form.
- **The response.** [Response](/endpoints/images-list/response/)
  states the responses and the sequence of the main stream.
- **The channels.** The client opens the one channel of
  [Client Channels](/endpoints/images-list/client/), the cancel. The
  server opens no channel on a list scope.
- **The listing.** The listing is zero or more images. The listing
  contains every image in the client's Store, as
  [Image sources](/endpoints/#image-sources) defines it — every image
  the client built by an [images::build](/endpoints/images-build/)
  request or pushed by an [images::push](/endpoints/images-push/)
  request and has not deleted by an
  [images::delete](/endpoints/images-delete/) request — and no other
  image. An image is named by its `digest` alone: the client names an
  image of the listing by its digest in an
  [images::stat](/endpoints/images-stat/),
  [images::edit](/endpoints/images-edit/),
  [images::hash](/endpoints/images-hash/) and
  [images::delete](/endpoints/images-delete/) request, and in a
  container request. No image has a name. An image absent from the
  listing is one the client cannot name. The Containerfile an image
  was built from is reported by [images::stat](/endpoints/images-stat/),
  one image at a time.
- **The client.** The client is the identity under which the
  connection was authorized, as [Authorization](/authorization/)
  provides. The listing is that identity's Store, and contains no
  image that is in another identity's Store and not in that
  identity's.
- **No eviction.** The server does not remove an image from the
  listing on its own account. An image stays listed until the client
  deletes it.

## The order

1. **The server reads the request.** A request whose payload has no
   byte is not a request of any endpoint, as [Endpoints](/endpoints/)
   provides.
2. **The server sends the listing.** The server sends every image in
   the client's Store, one response each, the byte `0` followed by the
   image. A client whose Store holds no image is sent none.
3. **The server says the listing is whole.** The server sends exactly
   one response whose payload is the byte `3` and nothing else. The
   server sends it exactly once on a scope, after every response of
   step 2 and before any other response.
4. **The server keeps the listing.** For the life of the scope: when
   the server has sent the byte `1` of an
   [images::build](/endpoints/images-build/) request by the client, or
   the byte `1` of an [images::push](/endpoints/images-push/) request
   by the client, it sends the image as added; when it has sent the
   byte `0` of an [images::edit](/endpoints/images-edit/) request by
   the client, it sends the image as changed; when it has sent the
   byte `0` of an [images::delete](/endpoints/images-delete/) request
   by the client, it sends the image as removed.
5. **The server ends the scope.** When the server receives the
   client's [cancel](/endpoints/images-list/client/cancel/), or the
   client's connection ends, the server sends the response finish.
   When the server cannot list, it sends the byte `5` followed by an
   error and the response finish.

## The rules that hold throughout

- **No end of its own.** The server does not end the scope because
  the client's Store holds no image, nor because every image listed
  has been removed. The client's cancel, the client's connection
  ending, and an error are the only ends.
- **Once per digest.** The server sends an image as added exactly
  once while it is listed, and as removed exactly once, only after it
  was sent as added. An image deleted and then built or pushed again
  is sent as removed and then as added.
- **Changed is the description.** The server sends an image as
  changed only after it was sent as added and before it is sent as
  removed, and only for an edit of its description. The `digest`,
  `bytes` and `created` of an image sent as changed equal those it was
  sent as added with. No other change to an image exists.
- **An empty listing.** The byte `3` with no response before it
  states that the client's Store holds no image. An empty listing is
  not an error.
- **The error.** An error states that the server did not list, or
  could not keep listing, and that nothing is determined about the
  client's Store from the moment it is sent. Responses sent before
  the error were sent as the listing stood. An error is not an empty
  listing.
- **No Store.** A server that holds out no
  [`images_store`](/capabilities/#images_store) capability keeps no
  Store and answers every request of this endpoint with exactly one
  response, the byte `4` alone, and the response finish, before
  anything is looked up; it sends no image, no byte `3` and serves no
  channel. Every other requirement of this page holds for a server
  that holds the capability out.
