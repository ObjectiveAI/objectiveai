summary: 'Responses of the byte 0, 1 or 2 followed by one image in the postcard wire format, added, changed or removed; the byte 3, once, when the listing is whole; the byte 4, alone and first, when the server keeps no Store; or the byte 5 followed by an error as one JSON value, last; or the byte 6, alone and first, when the connection has an image listing open already; and the response finish.'

```text
[0][image, postcard …]   per image added
[1][image, postcard …]   per description edited, after the image was added
[2][image, postcard …]   per image removed, after it was added
[3]                      once, when the listing is whole
[4]                      once, alone: the server keeps no Store
[5][error JSON …]        at most once, last
[6]                      once, alone: a listing is open on the connection already
```

- **The sequence.** Zero or more responses of the byte `0` followed
  by one image, one per image in the client's Store when the scope
  opened; exactly one response of the byte `3` and nothing else; then
  zero or more responses of the byte `0`, `1` or `2`, each followed
  by one image, as images enter the Store, have their descriptions
  edited and are deleted; the response finish follows the last of
  them, when the client cancels or the client's connection ends. Or:
  the responses sent so far, exactly one response of the byte `5`
  followed by an error, and the response finish. Or: exactly one
  response of the byte `4` and nothing else, and the response finish.
  Or: exactly one response of the byte `6` and nothing else, and the
  response finish. No response follows the error. The server sends no
  response of the byte `1` or `2` before the byte `3`.
- **The image.** A payload whose first byte is `0`, `1` or `2`
  carries one image after that byte, running to the end of the
  payload. The image is the `Image` defined below, encoded as the
  postcard reading of [Notation](/endpoints/#notation) provides: its
  `digest` as a varint byte length followed by that many bytes of
  UTF-8; followed by `description` as the byte `0`, or as the byte
  `1` followed by a varint byte length and that many bytes of UTF-8;
  followed by `bytes` as a varint; followed by `created` as a varint.
- **Added.** A response of the byte `0` states that the image is in
  the client's listing. The server sends it exactly once per digest
  while the image is listed: for every image listed when the scope
  opened, before the byte `3`; for an image that enters the Store
  after, when the server has sent the byte `1` of its
  [images::build](/endpoints/images-build/) or of its
  [images::push](/endpoints/images-push/).
- **Changed.** A response of the byte `1` states that the description
  of an image in the listing was edited, and carries the image as it
  is after the edit. The server sends it when it has sent the byte `0`
  of an [images::edit](/endpoints/images-edit/) of the image whose
  description differs from the description the server last sent for
  the image on this scope, and only for an image it has sent as added
  on this scope and not since as removed. An edit that leaves the
  description as it was causes no response on this scope. Its `digest`, `bytes` and `created` equal those the image
  was sent as added with.
- **Removed.** A response of the byte `2` states that the image is no
  longer in the client's listing, and carries the image as the server
  last sent it. The server sends it only for an image it has sent as
  added on this scope and not since as removed, and exactly once for
  it.
- **Whole.** A payload that is the byte `3` and nothing else states
  that every image in the client's Store when the scope opened has
  been sent as added. A client that wants the listing once reads to
  this byte and [cancels](/endpoints/images-list/client/cancel/). A
  payload whose first byte is `3` is read by that byte alone; bytes
  after it are not read.
- **`digest`.** The manifest digest of the image as the server holds
  it, UTF-8, of the form `<algorithm>:<hex>`. The digest is the key of
  the listing and the only name of the image: no two images listed at
  once share a digest. A container request of the client naming this
  digest names this image, and the server runs it from the client's
  Store, as [Image sources](/endpoints/#image-sources) states.
- **`description`.** What the client said of the image: absent, or a
  description as [The description](/authorization/#the-description)
  defines it. The server sets it from the `description` of the
  [images::build](/endpoints/images-build/) or the
  [images::push](/endpoints/images-push/) request by which the image
  entered the Store. Every [images::edit](/endpoints/images-edit/) of
  the image that the server answers with the byte `0` replaces it with
  the `description` of that edit, and an edit with no description
  leaves the image with none.
- **`bytes`.** The size of the image, in bytes, as the server counts
  it against the capacity of the Store.
- **`created`.** The time at which the image entered the client's
  Store — the end of its build or of its push — in seconds since
  `1970-01-01T00:00:00Z`, unsigned.
- **Order.** The order of the images is not prescribed. A client
  reads nothing into the position of an image.
- **A finish with nothing before it.** The request was not served, as
  [Endpoints](/endpoints/) provides, or the client cancelled before the
  server had sent anything. The server does not say which.
- **Unsupported.** A payload that is the byte `4` and nothing else
  states that the server holds out no
  [`images_store`](/capabilities/#images_store) capability and keeps
  no Store, as [Capabilities](/capabilities/) provides. It is the only
  response of the scope, sent before anything is looked up; bytes
  after it are not read.
- **Already open.** A payload that is the byte `6` and nothing else
  states that an images::list scope is open on the connection already,
  as [One open at a time](/endpoints/#one-open-at-a-time) provides. It
  is the only response of the scope, sent before anything is looked
  up; bytes after it are not read.
- **The error.** A payload whose first byte is `5` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0` to `6`, a payload whose bytes after `0`, `1` or `2`
  do not decode as one image, and a payload whose bytes after `5` are
  not one JSON value are malformed.
