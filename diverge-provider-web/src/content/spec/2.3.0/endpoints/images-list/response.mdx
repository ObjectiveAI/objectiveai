summary: 'Responses of the byte 0 or 1 followed by one image in the postcard wire format, added or removed; the byte 2, once, when the listing is whole; the byte 3, alone and first, when the server keeps no client image; or the byte 4 followed by an error as one JSON value, last; and the response finish.'

```text
[0][image, postcard …]   per image added
[1][image, postcard …]   per image removed, after it was added
[2]                      once, when the listing is whole
[3]                      once, alone: the server keeps no client image
[4][error JSON …]        at most once, last
```

- **The sequence.** Zero or more responses of the byte `0` followed
  by one image, one per image the client had built when the scope
  opened; exactly one response of the byte `2` and nothing else; then
  zero or more responses of the byte `0` or `1`, each followed by one
  image, as images are built and deleted; the response finish follows
  the last of them, when the client stops or the client's connection
  ends. Or: the responses sent so far, exactly one response of the
  byte `4` followed by an error, and the response finish. Or: exactly
  one response of the byte `3` and nothing else, and the response
  finish. No response follows the error. The server sends no
  response of the byte `1` before the byte `2`.
- **The image.** A payload whose first byte is `0` or `1` carries one
  image after that byte, running to the end of the payload. The image
  is the `Image` defined below, encoded as the postcard reading of
  [Notation](/endpoints/#notation) provides: its `name` as a varint
  byte length followed by that many bytes of UTF-8, followed by
  `digest` as a varint byte length followed by that many bytes of
  UTF-8, followed by `bytes` as a varint, followed by `created` as a
  varint.
- **Added.** A response of the byte `0` states that the image is in
  the client's listing. The server sends it exactly once per name
  while the image is listed: for every image listed when the scope
  opened, before the byte `2`; for an image built after, when the
  server has sent the byte `1` of its
  [images::build](/endpoints/images-build/).
- **Removed.** A response of the byte `1` states that the image is no
  longer in the client's listing, and carries the image as the server
  sent it as added. The server sends it only for an image it has sent
  as added on this scope and not since as removed, and exactly once
  for it.
- **Whole.** A payload that is the byte `2` and nothing else states
  that every image the client had built when the scope opened has
  been sent as added. A client that wants the listing once reads to
  this byte and [stops](/endpoints/images-list/client/stop/). A
  payload whose first byte is `2` is read by that byte alone; bytes
  after it are not read.
- **`name`.** The name of the image, UTF-8: the name the client's
  [images::build](/endpoints/images-build/) request gave it. The name
  is the handle of an image in this family: [images::stat](/endpoints/images-stat/)
  and [images::delete](/endpoints/images-delete/) name an image by
  this string. No two images listed at once share a name.
- **`digest`.** The manifest digest of the image as the server holds
  it, UTF-8, of the form `<algorithm>:<hex>`. A container request of
  the client naming this digest names this image, and the server
  runs it from what it holds, as the [containers::agents::run](/endpoints/containers-agents-run/)
  and [containers::tools::run](/endpoints/containers-tools-run/)
  pages state.
- **`bytes`.** The size of the image, in bytes, as the server counts
  it against the capacity of its store.
- **`created`.** The time at which the build ended, in seconds since
  `1970-01-01T00:00:00Z`, unsigned.
- **Order.** The order of the images is not prescribed. A client
  reads nothing into the position of an image.
- **A finish with nothing before it.** The request was not served, as
  [Endpoints](/endpoints/) provides, or the client stopped before the
  server had sent anything. The server does not say which.
- **Unsupported.** A payload that is the byte `3` and nothing else
  states that the server holds out no
  [`images_store`](/capabilities/#images_store) capability and keeps
  no client image, as [Capabilities](/capabilities/) provides. It is
  the only response of the scope, sent before anything is looked up;
  bytes after it are not read.
- **The error.** A payload whose first byte is `4` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0` to `4`, a payload whose bytes after `0` or `1` do
  not decode as one image, and a payload whose bytes after `4` are
  not one JSON value are malformed.
