A client opens the scope with a request whose payload is the tag byte
`28` and nothing more. The server sends every identity connected to
it whose [discover flag](/authorization/#the-discover-flag) is `1` or
`2`, one response each with the description its flag `2` carried and
the IP and the address of its connection, then the word that the
listing is whole, and keeps the scope open: an
identity whose connection opens with the flag `1` or `2` is sent as
added, and an identity whose connection ends is sent as
removed, for as long as the scope lives. The scope ends at the
client's cancel or at the client's connection ending; the response
finish follows, and no frame follows the finish. A connection holds
at most one discover scope open at a time, as
[One open at a time](/endpoints/#one-open-at-a-time) provides.

- **The request.** The request carries no parameter; the tag is the
  whole of it. [Request](/endpoints/discover/request/) states its
  form.
- **The response.** [Response](/endpoints/discover/response/) states
  the responses and the sequence of the main stream.
- **The channels.** The client opens the one channel of
  [Client Channels](/endpoints/discover/client/), the cancel. The server
  opens no channel on a discover scope.
- **The listing.** The listing is zero or more identities. An
  identity is in the listing exactly when a connection authorized
  under it is open to the server and that connection's client sent
  the discover flag `1` or `2`, whether the client was the connector
  or the connectee. Each identity is listed with the description that
  connection's flag `2` carried, or with none under the flag `1`; with
  the IP of the connection's other end; and, when the server is the
  connection's connector, with the dial target the server dialled the
  client at. An identity whose connection carried the flag `0` is not
  in the listing. An identity with no open connection is not in the
  listing.
- **The asking client.** The server serves the request for every
  client it serves. The asking client's own identity is in the listing
  when its own connection carried the flag `1` or `2`.

## The order

1. **The server reads the request.** A request whose payload has no
   byte is not a request of any endpoint, as [Endpoints](/endpoints/)
   provides.
2. **The server sends the listing.** The server sends every identity
   in the listing, one response each, the byte `0` followed by the
   identity, its description, its IP and its address. A server with no identity in the listing sends none.
3. **The server says the listing is whole.** The server sends exactly
   one response whose payload is the byte `2` and nothing else. The
   server sends it exactly once on a scope, after every response of
   step 2 and before any other response.
4. **The server keeps the listing.** For the life of the scope: when
   a connection whose client sent the flag `1` or `2` completes its
   authorization, the server sends that connection's identity as
   added; when such a connection ends, the server sends its identity
   as removed.
5. **The server ends the scope.** When the server receives the
   client's [cancel](/endpoints/discover/client/cancel/), or the client's
   connection ends, the server sends the response finish.

## The rules that hold throughout

- **No end of its own.** The server does not end the scope because
  the listing is empty, nor because every identity listed has been
  removed. The client's cancel and the client's connection ending are
  the only ends.
- **Once per identity.** An identity holds at most one connection to
  the server at a time. The server sends an identity as added exactly
  once while it is listed, and as removed exactly once, only after it
  was sent as added. An identity whose connection ends and whose
  identity connects again with the flag `1` or `2` is sent as removed
  and then as added. The server sends no identity as changed: a
  description, an IP and an address are the connection's, and do not
  change while the identity is listed.
- **An empty listing.** The byte `2` with no response before it
  states that no identity is in the listing. An empty listing is not
  an error.
- **No error.** This endpoint defines no error and no refusal. Every
  server serves it, and no capability governs it.
