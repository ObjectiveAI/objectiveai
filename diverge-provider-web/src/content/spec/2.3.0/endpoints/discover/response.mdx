title: 'Response'
summary: 'Responses of the byte 0 or 1 followed by one identity, its description, its IP, its address and whether it listens in the postcard wire format, added or removed; the byte 2, once, when the listing is whole; the byte 3 or 4 followed by one identity alone, when a listed identity comes to listen or stops; or the byte 5, alone and first, when the connection has a discover listing open already; and the response finish.'
order: 2

```text
[0][identity, description, ip, address, listening, postcard …]   per identity added
[1][identity, description, ip, address, listening, postcard …]   per identity removed, after it was added
[2]                                                              once, when the listing is whole
[3][identity, postcard …]                                        per listen opened, after the identity was added
[4][identity, postcard …]                                        per listen closed, after the identity was added
[5]                                                              once, alone: a listing is open on the connection already
```

- **The sequence.** Zero or more responses of the byte `0` followed
  by one identity, one per identity in the listing when the scope
  opened; exactly one response of the byte `2` and nothing else; then
  zero or more responses of the byte `0` or `1`, each followed by one
  identity, as discoverable identities connect and disconnect, and
  zero or more responses of the byte `3` or `4`, each followed by one
  identity, as listed identities come to listen and stop. The response
  finish follows the last of them, when the client cancels or the
  client's connection ends. Or: exactly one response of the byte `5`
  and nothing else, and the response finish. The server sends no
  response of the byte `1`, `3` or `4` before the byte `2`.
- **The item.** A payload whose first byte is `0` or `1` carries one
  item after that byte, running to the end of the payload. The item is
  `identity`, followed by `description`, followed by `ip`, followed by
  `address`, followed by `listening`, encoded as the postcard reading
  of [Notation](/endpoints/#notation) provides.
- **`identity`.** The pair of `issuer` and `subject`: `issuer` as a
  varint byte length followed by that many bytes of UTF-8, followed by
  `subject` as a varint byte length followed by that many bytes of
  UTF-8.
- **`description`.** The description the identity's authorization
  frame carried, as [Authorization](/authorization/#the-description)
  defines one. The byte `0` states that it carried none, under the
  flag `1`. The byte `1` followed by a varint byte length and that
  many bytes of UTF-8 states the description it carried under the
  flag `2`.
- **`ip`.** The IP of the other end of the identity's connection to
  the server: the IP the client dialled the server from, when the
  client is the connector, and the IP the server dialled the client
  at, when the server is the connector. The byte `0` followed by
  exactly 4 bytes states an IPv4 address, in network order. The byte
  `1` followed by exactly 16 bytes states an IPv6 address, in network
  order.
- **`address`.** The dial target the server dialled the client at,
  as the server's configuration states it: a `host:port` or a URL.
  The byte `0` states that the server did not dial the client, the
  client being the connector. The byte `1` followed by a varint byte
  length and that many bytes of UTF-8 states the dial target. An
  address is never an IP.
- **`listening`.** One byte. The byte `1` states that a
  [messages::listen](/endpoints/messages-listen/) scope is open under
  the identity as the item is sent. The byte `0` states that none is.
  `listening` is the one member of an item that changes while the
  identity is listed.
- **`issuer`.** The `iss` claim of the token under which the
  identity's connection was authorized, as
  [Authorization](/authorization/) provides.
- **`subject`.** The `sub` claim of that token.
- **Added.** A response of the byte `0` states that the identity is
  in the listing. The server sends it exactly once while the identity
  is listed: for every identity listed when the scope opened, before
  the byte `2`; for an identity listed after, when its connection has
  completed its authorization.
- **Removed.** A response of the byte `1` states that the identity is
  no longer in the listing, and carries the item exactly as the server
  sent it as added. The server sends it only for an identity it has
  sent as added on this scope and not since as removed, and exactly
  once for it.
- **Listening.** A response of the byte `3` carries, after that byte,
  one identity in the form of `identity`, running to the end of the
  payload, and nothing else. It states that a listen scope opened under
  that identity. A response of the byte `4` carries the same, and
  states that the identity's listen scope closed. The server sends
  either only for an identity it has sent as added on this scope and
  not since as removed, and only when it changes what the server last
  stated of the identity's `listening`. A response of the byte `1`
  carries the item with its `listening` as the responses of the byte
  `3` and `4` left it.
- **Whole.** A payload that is the byte `2` and nothing else states
  that every identity in the listing when the scope opened has been
  sent as added. A client that wants the listing once reads to this
  byte and [cancels](/endpoints/discover/client/cancel/). A payload whose
  first byte is `2` is read by that byte alone; bytes after it are not
  read.
- **Already open.** A payload that is the byte `5` and nothing else
  states that a discover scope is open on the connection already, as
  [One open at a time](/endpoints/#one-open-at-a-time) provides. It
  is the only response of the scope, sent before anything is listed;
  bytes after it are not read. It is the only response of this
  endpoint that refuses.
- **Order.** The order of the identities is not prescribed. A client
  reads nothing into the position of an identity.
- **A finish with nothing before it.** The request was not served, as
  [Endpoints](/endpoints/) provides, or the client cancelled before the
  server had sent anything. The server does not say which.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0` to `5`, a payload whose bytes after `0` or `1` do not
  decode as one item, its description, its IP, its address and its
  `listening` among them, and a payload whose bytes after `3` or `4` do
  not decode as one identity are malformed.
