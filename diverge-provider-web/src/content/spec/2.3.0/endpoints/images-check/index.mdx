A client opens the scope with a request whose payload is the tag byte
`14` followed by the image's digest and references, and the sources
the server is to look in. The server sends exactly one response,
which is the answer, the word that no source was asked, or an error.
The response finish follows the response, and no frame follows the
finish.

- **The request.** The request names a manifest digest and zero or
  more references, each a registry host and a repository path, and
  states which of three sources the server is to look in. The digest
  identifies the image; a reference states where the client knows
  the bytes to be. [Request](/endpoints/images-check/request/)
  states its form.
- **The sources.** `client` is the images the client built on the
  server by [images::build](/endpoints/images-build/) and has not
  deleted, and no image another client built. `server` is the images
  the server holds on its own account, which no client built. `registries`
  is every referenced registry the server's policy lists, asked as
  `<registry>/<name>@<digest>`; the server ignores a reference naming
  a registry its policy does not list, and a request naming no
  reference asks nothing of this source. Any combination may be
  asked. The server looks in the local sources asked before it asks a
  registry, and asks a registry only when no local source asked has
  the image.
- **The answer.** The answer is exactly `{"type":"available"}` or
  exactly `{"type":"unavailable"}`. The available answer states
  that at least one source asked has the image, at the time of the
  answer, for a container request naming that digest. The
  unavailable answer states that no source asked has it; a container
  request naming the image may still succeed where the client holds
  the image and the server obtains it from the client, or where a
  source not asked has it. Neither answer states which source.
  [Response](/endpoints/images-check/response/) states their form.
- **No source.** A request that asks for none of the three sources is
  answered with the byte `2` alone. The server looks nowhere, and
  nothing is determined about the image.
- **The error.** An error states that the server did not answer the
  question, and that nothing was determined about the image. An
  error is not an unavailable answer.
