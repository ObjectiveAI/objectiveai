summary: 'Tag 22: a client names an image of its Store by digest; the server sends exactly one response stating that the image is no longer in the client’s Store, that a running container runs it and it was not deleted, or an error, and the scope finishes; the deletion is not reversible.'
order: 22

---

A client opens the scope with a request whose payload is the tag byte
`22` followed by the digest of an image. The server sends exactly one
response, which states that the image is deleted, that a running
container of the client runs the image and it was not deleted, that
the server keeps no Store, or an error. The response finish follows
the response, and no frame follows the finish.

- **The request.** The request carries the digest of one image.
  [Request](/endpoints/images-delete/request/) states its form.
- **The image named.** The client names an image by the `digest` its
  [images::list](/endpoints/images-list/) listing gave it. The server
  resolves the digest against the Store of the identity under which
  the connection was authorized, as [Authorization](/authorization/)
  provides. A digest of no image in the client's Store is answered
  with an error. A client cannot delete an image from another
  client's Store.
- **The deletion.** When the server sends the byte `0`, the image is
  no longer in the client's Store. From that moment, every
  [images::list](/endpoints/images-list/) scope the client opens
  omits the image, and every list scope the client holds open that
  was sent the image as added is sent it as removed. The digest then
  names no image of the client's Store, and every request of this
  family by the client naming it is answered as for a digest of no
  image in the client's Store, until an
  [images::build](/endpoints/images-build/) or an
  [images::push](/endpoints/images-push/) request by the client
  brings an image of that digest into the client's Store again. An
  [images::check](/endpoints/images-check/) by the client naming the
  digest is answered as for any image that is not in the client's
  Store. [Response](/endpoints/images-delete/response/) states the
  form of the response.
- **Other Stores.** The deletion removes the image from the client's
  Store alone. An image of the same digest in another identity's Store
  is unaffected by it. The server keeps every manifest and every blob
  that an image in another identity's Store references, and removes
  the bytes of the image that nothing else it keeps references. The
  room those bytes took is the Store's again.
- **One request.** The request is the whole of the exchange. No frame
  precedes it, no confirmation follows it, and the deletion is not
  reversible.
- **An image in use.** When, at the time of the request, a running
  container of the client runs the image, the server does not delete
  it and sends the byte `1`. The image and the client's listing are
  as they were before the request. The server does not send the byte
  `0` for an image a running container of the client runs at the time
  of the request.
- **The error.** An error states that the server did not delete the
  image, for a reason other than a running container. The client's
  Store and listing are as they were before the request.
- **No Store.** A server that holds out no
  [`images_store`](/capabilities/#images_store) capability keeps no
  Store and answers every request of this endpoint with exactly one
  response, the byte `2` alone, and the response finish, before
  anything is looked up. Every other requirement of this page holds
  for a server that holds the capability out.
