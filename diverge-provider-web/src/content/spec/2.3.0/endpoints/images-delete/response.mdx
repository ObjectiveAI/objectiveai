The server sends exactly one response on the scope. The response
finish follows the response, and no frame follows the finish.

```text
[0]
[1]
[2][error JSON …]
```

- **The sequence.** Exactly one response precedes the response
  finish, and nothing follows the finish. A response finish that no
  response precedes states that the request was not served, as
  [Endpoints](/endpoints/) provides; whether the image exists is then
  not stated, and the client learns it from an
  [images::list](/endpoints/images-list/) scope.
- **Deleted.** A payload whose first byte is `0` states that the
  image no longer exists. The server sends it after the image is
  gone. From the moment the server sends it, every `images::list`
  scope the client opens omits the image, and every list scope the
  client holds open that was sent the image as added is sent it as
  removed. The server sends nothing after the byte `0`, and a client
  ignores every byte that follows it.
- **In use.** A payload whose first byte is `1` states that a running
  container of the client runs the image at the time of the request,
  and that it was not deleted. The image and the client's listing are
  as they were before the request. The server sends nothing after the
  byte `1`, and a client ignores every byte that follows it.
- **The error.** A payload whose first byte is `2` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content. The error
  states that the image exists as a result of the request, as it did
  before it, and that the reason is not a running container.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0`, `1` and `2`, and a payload whose bytes after `2` are
  not one JSON value are malformed.
