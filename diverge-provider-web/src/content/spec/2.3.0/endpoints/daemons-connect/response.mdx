The server sends the byte `0` once, when the acceptor takes the
connection, and from then on one response per message the acceptor
sends; or exactly one error and the response finish. No frame bearing
the scope follows the finish.

```text
[0]                  once, when the acceptor took the connection
[1][error JSON …]    once, when it did not, and the finish follows
[2][message …]       per message of the acceptor's, after the byte 0
```

- **The sequence.** The first response is the byte `0` or an error.
  An error is followed by the response finish, and the connection
  never opened. After the byte `0`, the server sends zero or more
  frame responses, then the finish, and the finish carries no error:
  the acceptor hung up, the connector hung up, the accept scope
  ended, or the connector's connection ended. A response finish that
  no response precedes states that the request was not served, as
  [Endpoints](/endpoints/) provides.
- **The error.** A payload whose first byte is `1` carries, after
  that byte, exactly one JSON value in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  The server sends `{"kind":"missing"}` for an identity no accept
  scope is open under and `{"kind":"denied"}` for an acceptor that
  declined the connection or whose accept scope ended before it took
  the connection.
- **The message.** A payload whose first byte is `2` carries, after
  that byte, exactly one message of the relayed connection, verbatim
  as the acceptor sent it. The first such message is the acceptor's
  authorization frame, the answer, as
  [Authorization](/authorization/) states. Every later one is one
  frame of the acceptor's, sealed under the relayed connection's
  keys, as [Sealing](/sealing/) states. The server reads no message,
  and requires no form of one.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0`, `1` and `2`, and a payload whose bytes after the
  byte `1` do not parse as one JSON value are malformed.
