A client opens the scope with a request whose payload is the tag byte
`26` and nothing more. The server sends every identity connected to
it that holds a [daemons::announce](/endpoints/daemons-announce/)
scope open, one response each with the announcement that scope
carries and the IP and the address of its connection. The server
sends the word that the listing is whole after them, and keeps the
scope open: an identity whose announce scope opens is sent as added,
and an identity whose announce scope ends is sent as removed, for as
long as the scope lives. The scope ends at the
client's cancel or at the client's connection ending; the response
finish follows, and no frame follows the finish. A connection holds
at most one daemons::list scope open at a time, as
[One open at a time](/endpoints/#one-open-at-a-time) provides.

- **The request.** The request carries no parameter; the tag is the
  whole of it. [Request](/endpoints/daemons-list/request/) states its
  form.
- **The response.** [Response](/endpoints/daemons-list/response/) states
  the responses and the sequence of the main stream.
- **The channels.** The client opens the one channel of
  [Client Channels](/endpoints/daemons-list/client/), the cancel. The server
  opens no channel on a daemons::list scope.
- **The listing.** The listing is zero or more identities. An
  identity is in the listing exactly while a connection authorized
  under it is open to the server and a
  [daemons::announce](/endpoints/daemons-announce/) scope is open on
  that connection, whether the client was the connector or the
  connectee. Each identity is listed with the announcement that scope
  carries; with the IP of the connection's other end; and, when the
  server is the connection's connector, with the dial target the
  server dialled the client at. An identity whose connection holds no
  announce scope open is not in the listing. An identity with no open
  connection is not in the listing.
- **The asking client.** The server serves the request for every
  client it serves, whether or not the client holds an announce scope
  open. The asking client's own identity is in the listing exactly
  while its own connection holds an announce scope open.

## The order

1. **The server reads the request.** A request whose payload has no
   byte is not a request of any endpoint, as [Endpoints](/endpoints/)
   provides.
2. **The server sends the listing.** The server sends every identity
   in the listing, one response each, the byte `0` followed by the
   identity, its announcement, its IP, its address and whether it
   listens. A server with no identity in the listing sends none.
3. **The server says the listing is whole.** The server sends exactly
   one response whose payload is the byte `2` and nothing else. The
   server sends it exactly once on a scope, after every response of
   step 2 and before any other response.
4. **The server keeps the listing.** For the life of the scope: when
   an announce scope opens on a connection, the server sends that
   connection's identity as added; when that announce scope ends, at
   its client's cancel or at its connection ending, the server sends
   the identity as removed.
5. **The server ends the scope.** When the server receives the
   client's [cancel](/endpoints/daemons-list/client/cancel/), or the client's
   connection ends, the server sends the response finish.

## The rules that hold throughout

- **No end of its own.** The server does not end the scope because
  the listing is empty, nor because every identity listed has been
  removed. The client's cancel and the client's connection ending are
  the only ends.
- **Once per identity.** An identity holds at most one connection to
  the server at a time, and a connection holds at most one announce
  scope open at a time. The server sends an identity as added exactly
  once while it is listed, and as removed exactly once, only after it
  was sent as added. An identity whose announce scope ends and which
  opens another is sent as removed and, after that, as added. The
  server sends no identity as changed: an IP and an address are the
  connection's, an announcement is the announce scope's, and none of
  the three changes while the identity is listed.
- **An empty listing.** The byte `2` with no response before it
  states that no identity is in the listing. An empty listing is not
  an error.
- **No error.** This endpoint defines no error and no refusal. Every
  server serves it, and no capability governs it.
