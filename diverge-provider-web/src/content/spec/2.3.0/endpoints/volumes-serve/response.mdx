The server sends exactly one response on the scope, and sends it
before it serves any channel.

```text
[0]                      serving: the volume is held, and the asks are answered
[1][volume-mode JSON …]  not served: the volume is not in the mode the request means
[2][error JSON …]        not served
```

- **The sequence.** Exactly one response, first. After a response
  whose payload is exactly the one byte `0`, the scope stays open:
  the server sends no other response on the scope, answers every
  channel the client opens as [Client Channels](/endpoints/volumes-serve/client/) states,
  and sends the response finish after the last answer when the client
  stops. After a response whose first byte is `1` or `2`, the
  response finish follows the response, and no frame follows the
  finish. A response finish that no response precedes states that
  the request was not served, as [Endpoints](/endpoints/) provides.
- **Volume mode.** A payload whose first byte is `1` carries, after
  that byte as JSON, an object with the members `name`, a string, and
  `mode`, a string: the name the request gave, and the mode the
  volume is in, as the client's listing reports it, one of
  `persistent`, `ephemeral` and `read_only`. The server sends it when
  the request's `mode` is not the volume's, after it has held the
  volume and given the hold back; the volume is not served and is as
  it was.
- **The error.** A payload whose first byte is `2` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0`, `1` and `2`, a payload whose first byte is `0` and
  that has a byte after it, a payload whose bytes after `1` do not
  parse as the refusal, and a payload whose bytes after `2` are not
  one JSON value are malformed.
