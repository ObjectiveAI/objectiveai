---
title: 'Response'
summary: 'Responses of the byte 0, 1 or 2 followed by one volume in the postcard wire format, added, changed or removed; the byte 3, once, when the listing is whole; or the byte 4 followed by an error as one JSON value, last; and the response finish.'
order: 2
draft: false
---

```text
[0][volume, postcard …]   per volume added
[1][volume, postcard …]   per volume changed, after it was added
[2][volume, postcard …]   per volume removed, after it was added
[3]                       once, when the listing is whole
[4][error JSON …]         at most once, last
```

- **The sequence.** Zero or more responses of the byte `0` followed
  by one volume, one per volume available to the client when the
  scope opened; exactly one response of the byte `3` and nothing
  else; then zero or more responses of the byte `0`, `1` or `2`, each
  followed by one volume, as volumes are created, edited and deleted;
  the response finish follows the last of them, when the client stops
  or the client's connection ends. Or: the responses sent so far,
  exactly one response of the byte `4` followed by an error, and the
  response finish. No response follows the error. The server sends no
  response of the byte `1` or `2` before the byte `3`.
- **The volume.** A payload whose first byte is `0`, `1` or `2`
  carries one volume after that byte, running to the end of the
  payload. The volume is the `Volume` defined below, encoded as the
  postcard reading of [Notation](/endpoints/#notation) provides: its
  `name` as a varint byte length followed by that many bytes of
  UTF-8, followed by `bytes` as a varint, followed by `created` as a
  varint, followed by `mode` as one byte.
- **Added.** A response of the byte `0` states that the volume is
  available to the client. The server sends it exactly once per name
  while the volume is listed: for every volume available when the
  scope opened, before the byte `3`; for a volume that becomes
  available after, when it does.
- **Changed.** A response of the byte `1` states that the volume's
  `bytes` or `mode` are now what the response carries. The server
  sends it only for a volume it has sent as added on this scope and
  not since as removed, and only when `bytes` or `mode` differ from
  what it last sent for that name. The `name` and the `created` of a
  volume do not change.
- **Removed.** A response of the byte `2` states that the volume is
  no longer available to the client, and carries the volume as the
  server last sent it. The server sends it only for a volume it has
  sent as added on this scope and not since as removed, and exactly
  once for it.
- **Whole.** A payload that is the byte `3` and nothing else states
  that every volume available to the client when the scope opened has
  been sent as added. A client that wants the listing once reads to
  this byte and [stops](/endpoints/volumes-list/client/stop/). A
  payload whose first byte is `3` is read by that byte alone; bytes
  after it are not read.
- **`name`.** The name of the volume, UTF-8. The name is the only
  handle of a volume: every request of this specification that names
  a volume names it by this string. No two volumes listed at once
  share a name.
- **`bytes`.** The size of the volume, in bytes. For a volume the
  client created, `bytes` is the size the client last stated for it,
  in its [volumes::create](/endpoints/volumes-create/) request or in a
  later [volumes::edit](/endpoints/volumes-edit/) request. The number
  of bytes in use is reported by
  [volumes::stat](/endpoints/volumes-stat/).
- **`created`.** The time at which the volume came into being, in
  seconds since `1970-01-01T00:00:00Z`, unsigned. What "came into
  being" marks is the server's to determine.
- **`mode`.** The mode of the volume, as one byte, the postcard
  discriminant of the enum: `0` is `persistent`, `1` is `ephemeral`,
  `2` is `read_only`. For a volume the client created, `mode` is the
  mode the client last stated for it, in its
  [volumes::create](/endpoints/volumes-create/) request or in a later
  [volumes::edit](/endpoints/volumes-edit/) request; for another
  volume, the mode is the server's to determine. What each mode means
  for a container that mounts the volume, for a
  [volumes::serve](/endpoints/volumes-serve/) of it, and for how many
  may hold it at once, [volumes::create](/endpoints/volumes-create/)
  states. Every container the client mounts the volume in and every
  serve of it is bound under this mode. A byte other than `0`, `1` and
  `2` does not decode.
- **Order.** The order of the volumes is not prescribed. A client
  reads nothing into the position of a volume.
- **A finish with nothing before it.** The request was not served, as
  [Endpoints](/endpoints/) provides, or the client stopped before the
  server had sent anything. The server does not say which.
- **The error.** A payload whose first byte is `4` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value. This revision prescribes nothing about its
  content.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0`, `1`, `2`, `3` and `4`, a payload whose bytes after
  `0`, `1` or `2` do not decode as one volume, and a payload whose
  bytes after `4` are not one JSON value are malformed.
