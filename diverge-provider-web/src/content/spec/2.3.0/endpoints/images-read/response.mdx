The server sends exactly one response on the main stream, as the first
frame of the main stream. No further response follows it. The response
finish follows it, and no frame follows the finish.

```text
[0]                    once, first: the server holds the image; the scope stays open
[1]                    once, alone: the server does not hold the image
[2]                    once, alone: the server has neither a Store nor any registry
[3][error JSON …]      once, alone: no answer
```

- **The sequence after a refusal.** After the byte `1`, the byte `2`
  or an error, the response finish follows the response, and the
  server answers no channel of the scope.
- **The sequence after the held answer.** After the byte `0`, the
  server sends no further response. Every answer comes on the channel
  of the ask it answers. The response finish follows the client's
  [cancel](/endpoints/images-read/client/cancel/), after the last
  answer of every channel still open when the server receives it, or
  the end of the client's connection.
- **Held.** A payload that is the byte `0` and nothing else states
  that the server can supply the image the digest names from the
  client's Store, where the client owns the digest, or otherwise from
  a registry in its
  [`images_registries`](/capabilities/#images_registries) that a
  reference of the request names, as
  [images::read](/endpoints/images-read/) states. It states what the
  server determined at the time of the answer, names no source, and
  reserves nothing.
- **Not found.** A payload that is the byte `1` and nothing else
  states that the server cannot supply the image from either source.
  It states no reason and names no source.
- **Unsupported.** A payload that is the byte `2` and nothing else
  states that the server holds out no
  [`images_store`](/capabilities/#images_store) capability and that
  its [`images_registries`](/capabilities/#images_registries) is
  empty, as [Capabilities](/capabilities/) provides. The server sends
  it before anything is looked up.
- **No bytes after the answer.** The server sends nothing after the
  byte `0`, the byte `1` or the byte `2`, and a client ignores every
  byte that follows any of them.
- **The error.** A payload whose first byte is `3` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content. The error
  states that the server did not answer the question and that nothing
  was determined about the image.
- **Not served.** A response finish that no response precedes states
  that the server will not serve the request, as
  [Endpoints](/endpoints/) provides for a request not served. The
  server serves no channel after it.
- **Malformed.** A payload with no byte, a payload whose first byte is
  none of `0`, `1`, `2` and `3`, and a payload whose bytes after `3`
  are not one JSON value are malformed.
