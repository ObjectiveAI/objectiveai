The server sends exactly one response on the scope. The response
finish follows the response, and no frame follows the finish.

```text
[0][stat, postcard …]    the volume, examined
[1]                      not examined: a running container holds the volume
[2]                      not examined: a FUSE serve holds the volume
[3]                      not examined: another operation holds the volume
[4]                      not examined: the server keeps no volume
[5][error JSON …]        not examined
```

- **The sequence.** Exactly one response precedes the response
  finish, and nothing follows the finish. A response finish that no
  response precedes states that the request was not served, as
  [Endpoints](/endpoints/) provides.
- **The stat.** A payload whose first byte is `0` carries the stat
  after that byte, running to the end of the payload. The stat is the
  `Stat` defined below, encoded as the postcard reading of
  [Notation](/endpoints/#notation) provides: `name` as a varint byte
  length followed by that many bytes of UTF-8, followed by `bytes` as
  a varint, followed by `created` as a varint, followed by `mode`
  as one byte, followed by `bytes_used` as a varint, followed by
  `dirhash` as a varint byte length followed by that many bytes of
  UTF-8.
- **`name`, `bytes`, `created`, `mode`.** The volume as the
  client's listing reports it, in the form the
  [volumes::list response](/endpoints/volumes-list/response/) defines.
  The four values equal those the listing reports for the volume at
  the time of the response.
- **`bytes_used`.** The number of bytes of the volume in use, at the
  time of the response.
- **`dirhash`.** The hash of the content of the volume, at the time
  of the response. It is the string that the Go package
  [`golang.org/x/mod/sumdb/dirhash`](https://pkg.go.dev/golang.org/x/mod/sumdb/dirhash),
  whose source is
  [`hash.go`](https://cs.opensource.google/go/x/mod/+/master:sumdb/dirhash/hash.go),
  returns from `HashDir(root, "", Hash1)` for the root of the volume,
  as that package defines it, which is the following. The files are
  every entry beneath the root that is not a directory as `lstat`
  reports it, each named by its path relative to the root with its
  components joined by `/`; a symbolic link is a file, opened through
  the link. The names are sorted bytewise. A name containing a
  newline is an error. For each file, in that order, one line is
  written into one SHA-256: the SHA-256 of the bytes of the file as
  lowercase hexadecimal, two spaces, the name, and a newline. The
  `dirhash` is the string `h1:` followed by that SHA-256 encoded as
  standard base64 with padding. A volume with no file has the
  `dirhash` `h1:47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=`. Two
  volumes with one `dirhash` have one content; two volumes with
  different `dirhash` values have different content.
- **The refusals, and their order.** The server decides the bytes
  `1`, `2` and `3` in the order [Capabilities](/capabilities/#the-hold)
  states for an operation, the first rule that applies deciding. On
  a server that keeps no volume, the byte `4` is the only response,
  sent before anything is looked up. Every refusal states that the
  volume was not examined and that nothing changed. A client ignores
  every byte that follows the byte `1`, `2`, `3` or `4`.
- **Mounted.** A payload that is the byte `1` and nothing else states
  that a running container of the client holds the volume at the
  time of the request.
- **FUSE served.** A payload that is the byte `2` and nothing else
  states that a [volumes::fuse_serve](/endpoints/volumes-fuse-serve/)
  of the client holds the volume at the time of the request.
- **Held.** A payload that is the byte `3` and nothing else states
  that the volume is under another `volumes::stat`, a
  [volumes::read](/endpoints/volumes-read/), a
  [volumes::write](/endpoints/volumes-write/), a
  [volumes::filetree](/endpoints/volumes-filetree/), a
  [volumes::edit](/endpoints/volumes-edit/) or a
  [volumes::delete](/endpoints/volumes-delete/) at the time of the
  request.
- **Unsupported.** A payload that is the byte `4` and nothing else
  states that the server holds out none of the three mode objects
  and keeps no volume, as [Capabilities](/capabilities/#the-volume-modes)
  provides.
- **The error.** A payload whose first byte is `5` carries an error
  after that byte, running to the end of the payload. The error is
  exactly one JSON value, in the form defined on the
  [volumes::list response](/endpoints/volumes-list/response/) page.
  This revision prescribes nothing about its content.
- **Malformed.** A payload with no byte, a payload whose first byte
  is none of `0` to `5`, a payload whose bytes after `0` do not
  decode as the stat, and a payload whose bytes after `5` are not one
  JSON value are malformed.
