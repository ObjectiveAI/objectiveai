The payload of the request is the tag byte followed by the request in
the postcard wire format, as the postcard reading of
[Notation](/endpoints/#notation) provides:

```text
[10][name_len: varint][name: utf8 …][bytes: varint][mode: 0 | 1 | 2]
```

- **`name`.** The name of the volume, UTF-8, preceded by its byte
  length as a varint. The name is the handle of the volume from the
  moment it exists: every request of this specification that names
  the volume names it by this string.
- **`bytes`.** The size of the volume, in bytes, as a varint. It is
  the size the client's listing reports as `bytes` for the volume. A
  later [volumes::edit](/endpoints/volumes-edit/) request changes it;
  nothing else does.
- **`mode`.** The mode the volume starts in, as one byte, the
  postcard discriminant of the enum: `0` is `persistent`, `1` is
  `ephemeral`, `2` is `read_only`, as
  [volumes::create](/endpoints/volumes-create/) defines the three. It
  is the mode the client's listing reports as `mode` for the volume.
  A later [volumes::edit](/endpoints/volumes-edit/) request changes
  it; nothing else does. A byte other than `0`, `1` and `2` does not
  decode.
- **Bytes after the request.** A server ignores every byte that
  follows the `mode` field. A request whose payload extends past the
  request is not malformed.
- **Malformed.** A payload with no byte, a payload whose first byte
  is not `10`, and a payload whose bytes after the tag do not decode
  as the request are malformed. [Endpoints](/endpoints/) states how a
  server answers a request it cannot read.
