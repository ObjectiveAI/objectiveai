The client opens this channel to send a batch of one or more messages
to the agent, in order. A batch sent while no loop runs starts one,
as its input; a batch sent while one runs is placed in its queue. The
server opens an enqueue channel on the begin scope of the container's
proxy with the batch, whole and unchanged, and relays the fate the
proxy answers. What the agent says in
reply is the main stream of the scope, as
[Response](/endpoints/containers-agents-run/response/) states.

- **The request.** The tag byte `7` followed by the batch as JSON.
  [Request](/endpoints/containers-agents-run/client/enqueue/request/) states its form.
- **The response.** Exactly one channel response, sent when the fate
  of the batch is known, however long that takes, and the channel
  response finish. The fate is the fate of every message of the
  batch. [Response](/endpoints/containers-agents-run/client/enqueue/response/)
  states the sequence.
- **Two kinds.** A request is a batch of chat messages or exactly one
  structured decision, as its `type` states. The paragraph above
  states what a batch of chat messages does. A structured decision is
  handed to the program alone, when the program has no run open, and
  nothing is handed to the program until the run it started has
  ended, as the proxy's
  [enqueue](/container-proxy-endpoints/agents-begin/client/enqueue/)
  channel states.
- **Order.** The server never splits a batch and never reorders its
  messages. The server relays each enqueue channel apart from every
  other, verbatim, the `index` included. The order in which the
  program is handed the requests of a scope is the order of their
  `index`, as the proxy's
  [enqueue](/container-proxy-endpoints/agents-begin/client/enqueue/)
  channel states, whether or not the client waits for one channel's
  answer before it opens the next.
