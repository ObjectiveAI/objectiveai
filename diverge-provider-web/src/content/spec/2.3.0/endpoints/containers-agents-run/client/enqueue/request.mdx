```text
[7][request JSON …]
```

- **`index`.** A `u64`: the place of the request among the enqueue
  channel requests of the scope. The client numbers them from `0`,
  one more for each, the two kinds of request alike.
- **`type`.** The string `chat` or the string `structured_decisions`,
  which states the kind of the request and its other members. The
  request carries no member beside `index`, `type`, and the members
  of its kind.
- **`messages`.** A request of type `chat` carries exactly one
  further member, `messages`: an array of one or more messages, the
  batch. The order of the array is the order in which the program
  takes the messages. Each message is an object with exactly the two
  members `key` and `content`. The server relays
  the request to the proxy verbatim, in one channel request.
- **A structured decision.** A request of type `structured_decisions`
  carries exactly three further members: `key`, a string, as a
  message's is; `content`, an array of MCP content blocks, as a
  message's is; and `questions`, an array of questions. Each question
  is an object with the members `id`, a string, `type`, and
  `instructions`, an array of MCP content blocks. The `type` of a
  question is `noul`, `choice`, or `score`. A question of type
  `choice` carries one further member, `options`, an array of objects
  each with the member `value`, a string, and at most one further
  member, `description`, an array of MCP content blocks. A question
  of type `score` carries one further member, `levels`, an array of
  arrays of MCP content blocks. A question carries no other member.
  The server does not read the questions.
- **`key`.** A string the client chooses, one for each message. Every
  user part of the message carries it on the main stream of the
  scope. Two messages may share one. The server relays it verbatim
  and does not read it. No channel withdraws a batch once it is sent.
- **`content`.** An array of MCP content blocks, in order, each as
  the `ContentBlock` of the crate's MCP dependency states one: text,
  an image, audio, an embedded resource, or a resource link. What the
  container makes of a block is its own. A container that cannot take
  a block refuses the whole batch, and the fate is the error, in the
  container's words. A message with no block is refused too.
- **Malformed.** A channel request whose payload does not decode as
  stated is answered by a channel response finish that no channel
  response precedes, and the server does nothing else for it.
