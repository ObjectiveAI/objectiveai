The server opens this channel when the `Begun` the proxy answered its
begin with carries one or more dependencies: the tool containers the
container's program declared when it was registered, each as a
dependency tool template, which the client deploys and serves to the
container under the template's name. The client's answer decides
whether the run goes on.

- **When.** After the begin has been answered and before the id is
  sent, beside the FUSE mounts. Exactly once per run, and never on a
  connect scope. The server opens no dependencies channel when the
  list is empty.
- **The request.** The tag byte `3` followed by the dependencies as
  JSON. [Request](/endpoints/containers-agents-run/server/dependencies/request/) states its form.
- **The response.** Exactly one channel response, deployed or an
  error, and the channel response finish.
  [Response](/endpoints/containers-agents-run/server/dependencies/response/) states the sequence.
- **Verbatim.** The server relays the list as the proxy sent it and
  reads none of it: not the mounts, not the database word, not the
  permissions.
- **What the client does.** The client runs each dependency as a
  [containers::tools::run](/endpoints/containers-tools-run/) from
  the template's `image`, `memory`, `disk` and `arguments`; serves
  the agent container's paths the template's mounts name into the
  tool container live, as [containers::serve](/endpoints/containers-serve/)
  serves them and a FUSE mount of the tools run mounts them; gives
  the tool the database the template's `database` names and an
  account holding the template's `permissions`; and serves the tool
  to the container under the template's `name` among the MCP servers
  the client answers the container's tool calls with. A tool
  container declares no dependencies of its own.
