The server opens this channel on the run scope when a
[containers::tools::list_for](/endpoints/containers-tools-list-for/) scope names the
identity of this run, whether the run was open when the list scope
opened or began after. The runner's answer decides whether the
container is sent on the list scope.

- **The request.** The tag byte `4` followed by the address and the
  identity as JSON. [Request](/endpoints/containers-tools-run/server/authorize-list/request/) states its form.
- **The response.** Exactly one channel response of one byte and the
  channel response finish. [Response](/endpoints/containers-tools-run/server/authorize-list/response/) states the
  sequence.
- **Two claims, both attested.** The address is the peer address of
  the lister's connection as the server observed it. The identity is
  the one under which the server authorized the lister's connection,
  as [Authorization](/authorization/) provides. The lister asserts
  nothing on this channel.
- **Every runner at once.** The server opens this channel on every
  tool run the identity holds, without waiting on any other's answer,
  and sends each container the moment its own answer arrives. No
  agent run is asked.
- **And every runner after.** While a list scope naming the identity
  is open, the server opens this channel on every tool run the
  identity begins, when that run has been answered with its id. The
  server opens it exactly once per container per list scope.
- **Seeing is not joining.** A yes tells the lister the container's
  id and family, and nothing else. A connector that joins is asked
  for on the [authorize-connect](/endpoints/containers-tools-run/server/authorize-connect/) channel,
  with its own authorization.
