The server opens this channel when a FUSE mount's scope on the
container's proxy carries the ask that renames an entry of a mount the client serves live.
The ask is relayed with the mount's `id` put in front of it — the
mount's scope is the mount, and its asks carry no id — and otherwise
verbatim; the client's one answer is relayed back.

- **The request.** The tag byte `22` followed by the ask in the form
  the [Container Proxy](/proxy/) layer defines for it, the mount's
  `id` added. [Request](/endpoints/containers-tools-run/server/fuse-rename/request/) states its
  form.
- **The response.** Exactly one channel response and the channel
  response finish. [Response](/endpoints/containers-tools-run/server/fuse-rename/response/)
  states the sequence.
- **The conduit.** The server relays the one channel response onto
  the mount's channel as one channel response and finishes it. The
  server does not read the ask or the answer, and does not send the
  ask twice.
- **Refusal is the client's.** A client that answers this ask with an error refuses the change, and the proxy reports the operation to the program as failed. The server relays the answer and decides nothing.
- **A directory mount only.** The proxy sends this ask only for a mount of `fuse_directory_mounts`.
