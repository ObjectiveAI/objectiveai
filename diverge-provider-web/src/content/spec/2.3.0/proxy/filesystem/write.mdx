The server opens `/filesystem/write` and sends the request below as
its first message, naming the destination; then the content, one
piece per message; then **one empty message**, which ends the
content. The container answers with exactly one message, then closes.

```text
server → container:   [request JSON] [bytes …] … [bytes …] []
container → server:   [kind: u8][message …]                   then the close
```

- **The empty message ends the content.** A piece is never empty;
  the first empty message is the end. The file is the pieces
  concatenated.
- **One answer.** Kind `0` is the file written. Kind `1` and a
  message is the file not written; a destination whose parent
  directory does not exist is such an error.
- **A close before the empty message abandons the write.** The
  destination is left as it was. An abrupt end from either party is
  a write that failed, and the destination is left as it was.
- **Nothing is repeated.**
