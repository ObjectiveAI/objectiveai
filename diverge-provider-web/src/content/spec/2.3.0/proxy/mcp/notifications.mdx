The ask is kind `4` on [`/requests`](/proxy/requests/); its payload
is empty. The server answers on `/mcp/notifications/{channel}` with
one message per notification, for as long as the path lives: each
the response frame below, its first byte `0` and the rest the
notification's JSON. An error — first byte `1`, the rest the error's
JSON — is the last message when there is one. The close ends the
stream. A path closed cleanly with no message is the stream not
served.

- **Asked once the container has exchanged.** The container asks for
  notifications after its first exchange of kinds `0` to `3`, and
  keeps one such ask open for the rest of its life.
- **A stream that ended is asked again**, on the next `/requests`
  connection, whether it ended cleanly, by an error, or abruptly.
  Notifications that occurred while no stream was open are not
  replayed.
