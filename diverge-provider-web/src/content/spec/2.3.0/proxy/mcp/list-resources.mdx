The ask is kind `1` on [`/requests`](/proxy/requests/); its
payload is the JSON of the params below, running to the end of the
message. The server answers on `/mcp/list-resources/{channel}` with exactly
one message — the response frame below, its first byte `0` for a
result or `1` for an error, the rest that variant's JSON — and then
the close. A path closed cleanly with no message is the exchange
not served. An abrupt end, or a `/requests` connection that ended
before the path was opened, is an exchange the container asks again
— see [MCP Exchanges](/proxy/mcp/).
