Five asks carry the container's operations on a key-value store the
caller holds. Each is one ask and one one-message answer.

| Kind | Ask | Payload after the kind | Answered on | With |
|------|-----|------------------------|-------------|------|
| `5` | get | `[key …]` | [`/vault/get/{channel}`](/proxy/vault/get/) | present, missing, or error |
| `6` | set | `[key_len: u16, big-endian][key …][value …]` | [`/vault/set/{channel}`](/proxy/vault/set/) | ok or error |
| `7` | delete | `[key …]` | [`/vault/delete/{channel}`](/proxy/vault/delete/) | ok or error |
| `8` | lock | `[ttl: u32, big-endian][key …]` | [`/vault/lock/{channel}`](/proxy/vault/lock/) | ok, once held, or error |
| `9` | unlock | `[key …]` | [`/vault/unlock/{channel}`](/proxy/vault/unlock/) | ok or error |

- **Keys and values.** A key is UTF-8, running to the end of the
  payload wherever nothing follows it; only `set` prefixes it with
  its length, because a value follows. A value is bytes, verbatim.
- **The namespace is the server's.** The payload names a key and no
  store; which store the key lands in is the server's determination
  for the container it serves, and the container has no way to name
  another's.
- **One message, then the close.** Every answer is exactly one
  message — the frame its page shows — then the close. A path closed
  cleanly with no message is the operation not served.
- **Nothing is repeated.** An operation whose path ended abruptly, or
  whose `/requests` connection ended before the path was opened, is
  reported to the container as failed and is not asked again. A lock
  the server granted outlives such an ending by its TTL.
