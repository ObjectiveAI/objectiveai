`/requests` carries every ask the proxy makes. The server opens the
path and holds it open. The server sends no message on it; every
message on the path is from the proxy, and every answer arrives on
another path.

```text
[channel: u32, big-endian][kind: u8][payload …]
```

- **The channel.** A `u32` that the proxy mints in ascending order
  and that is unique among the asks it has sent and the server has
  not yet answered. The channel names the answer path the server
  opens: `/mcp/list-tools/{channel}` for kind `0`, and so on through
  the table below.
- **The kind.** One byte designating the ask. The payload is the
  ask's own bytes in the form its page defines, running to the end of
  the message.

| Kind | Ask | Answered on |
|------|-----|-------------|
| `0` | MCP list tools | [`/mcp/list-tools/{channel}`](/proxy/mcp/list-tools/) |
| `1` | MCP list resources | [`/mcp/list-resources/{channel}`](/proxy/mcp/list-resources/) |
| `2` | MCP call tool | [`/mcp/call-tool/{channel}`](/proxy/mcp/call-tool/) |
| `3` | MCP read resource | [`/mcp/read-resource/{channel}`](/proxy/mcp/read-resource/) |
| `4` | MCP notifications | [`/mcp/notifications/{channel}`](/proxy/mcp/notifications/) |
| `5` | vault get | [`/vault/get/{channel}`](/proxy/vault/get/) |
| `6` | vault set | [`/vault/set/{channel}`](/proxy/vault/set/) |
| `7` | vault delete | [`/vault/delete/{channel}`](/proxy/vault/delete/) |
| `8` | vault lock | [`/vault/lock/{channel}`](/proxy/vault/lock/) |
| `9` | vault unlock | [`/vault/unlock/{channel}`](/proxy/vault/unlock/) |
| `10` | command | [`/command/{channel}`](/proxy/command/) |
| `11` | postgres | [`/postgres/{channel}`](/proxy/postgres/) |
| `12` | FUSE read | [`/fuse/read/{channel}`](/proxy/fuse/read/) |
| `13` | FUSE write | [`/fuse/write/{channel}`](/proxy/fuse/write/) |
| `14` | FUSE list | [`/fuse/list/{channel}`](/proxy/fuse/list/) |
| `15` | FUSE remove | [`/fuse/remove/{channel}`](/proxy/fuse/remove/) |
| `16` | FUSE rename | [`/fuse/rename/{channel}`](/proxy/fuse/rename/) |
| `17` | FUSE mkdir | [`/fuse/mkdir/{channel}`](/proxy/fuse/mkdir/) |
| `18` | FUSE stat | [`/fuse/stat/{channel}`](/proxy/fuse/stat/) |

- **One connection.** `/requests` accepts one connection at a time.
  While one is open, the proxy refuses a second with HTTP status
  `409` before the upgrade.
- **The connection ending.** When the connection ends, cleanly or
  abruptly, every ask announced on it and not yet answered is lost to
  the server. Each kind's page states what the proxy does with such
  an ask. An ask the proxy makes after the ending waits for the next
  connection.
