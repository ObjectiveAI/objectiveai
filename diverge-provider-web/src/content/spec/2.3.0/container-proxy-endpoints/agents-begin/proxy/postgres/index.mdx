The proxy opens this channel when a program in the container opens a
connection to the proxy's database listener. It is the proxy's half
of the connection; the server's half is a
[postgres](/container-proxy-endpoints/agents-begin/server/postgres/) channel the server opens,
quoting the same id.

- **The request.** The tag byte `0` followed by a connection id, four
  bytes, that the proxy minted. [Request](/container-proxy-endpoints/agents-begin/proxy/postgres/request/)
  states its form.
- **The response.** What the database says, as channel responses,
  and the channel response finish, which closes the driver's socket.
  [Response](/container-proxy-endpoints/agents-begin/proxy/postgres/response/) states the sequence.
- **The id.** The proxy chooses the id and keeps it unique among the
  connections it has announced and the server has not finished. The
  proxy does not reuse an id while either half of its connection is
  open.
- **Before the other half.** The proxy reads nothing from the driver
  until the server has opened its half. The proxy writes what arrives
  on this channel to the driver in order, and does not read it.
