summary: 'The server sends Begun once, carrying the dependencies the container declared and the secrets it takes, or an error and the finish; after Begun it sends Active before each loop, every chunk of that loop as a response, and Inactive carrying the rotating secrets after it, and the finish when the server ends or after the one error it sends when it cannot collect them.'

```text
[0][registration JSON …]    begun: the container holds its arguments, and these are its dependencies and its secrets
[1][error JSON …]           not begun: the connection had begun, or the arguments were refused; or, after begun, the rotating secrets could not be collected
[2][chunk JSON …]           one chunk of the conversation
[3]                         active: a loop began
[4][values JSON …]          inactive: that loop ended, and these are its rotating secrets
```

- **The sequence.** Exactly one response whose first byte is `0`,
  followed by zero or more loops, followed by the response finish
  when the server ends; or exactly one response whose first byte is
  `1`, followed by the response finish. A loop is exactly one
  response whose payload is the byte `3` and nothing else, followed
  by zero or more responses whose first byte is `2`, in the order the
  container produced them, followed by exactly one response whose
  first byte is `4`, or, where the server cannot collect the loop's
  rotating secrets, by exactly one response whose first byte is `1`
  and the response finish. The server sends no response whose first
  byte is `2`, `3` or `4` before `Begun`, none whose first byte is
  `2` outside a loop, and none after the finish.
- **Active and inactive.** The server sends the byte `3` when the
  agent's server answers the loop's `POST /run` with `2xx`, before
  the first chunk of that loop, and the byte `4` when the event
  stream of that answer ends, after the last chunk of that loop,
  whether the stream ended cleanly or by failing, and after the
  program has handed back the loop's rotating secrets. The server
  produces both itself and relays neither from the agent's server:
  every event of the agent's server is sent under the byte `2`, so
  no event is read as either. The byte `3` carries nothing after it.
  The server sends no byte `3` while a loop is open, and no byte `4`
  while none is.
- **The registration.** The bytes after the byte `0` are a JSON
  object of two members, each absent when empty: `dependencies`, an
  array of the dependency tool templates the container's program
  answered its registration with, each as the
  [registration](/endpoints/containers-agents-run/server/registration/)
  channel of the run defines one, in the order the program declared
  them; and `secrets`, an object whose every member is a secret's
  name, as the container's template declares it, to the mode the
  program takes it in, the string `fixed` or `rotating`, in the
  order the program declared them. The server sends both exactly as
  the program produced them and reads neither.
- **The values.** The bytes after the byte `4` are a JSON object
  whose every member is the name of a secret the program declared
  `rotating`, to the value the program leaves in it, any JSON value:
  every `rotating` name the program declared, and no other; the
  empty object for a program that declared none `rotating`. The
  server collects them from the program after the loop's stream
  ends, and sends them as the program handed them back. From the
  byte `4` the program holds no values, and the server delivers no
  message to a program that declared a secret until the next
  [secrets](/container-proxy-endpoints/agents-begin/client/secrets/)
  channel is answered `Fed`.
- **The chunk.** The bytes after the byte `2` are one chunk as the
  [containers::agents::run response](/endpoints/containers-agents-run/response/)
  defines it, as JSON, which the server sends as the agent's server
  produced it. The first chunks of a loop are the
  user parts of the message it started on — one chunk per content
  block, each carrying the message's `key` — or of every message it
  started on, in the order sent.
- **`_meta`.** The server sets nothing under `_meta`. Every member of
  `_meta`, and every other member of the chunk, is sent as the
  agent's server produced it.
- **The error.** After the byte `1`, exactly one JSON value in the
  form defined on the [volumes::list response](/endpoints/volumes-list/response/)
  page. Refused arguments carry the container's own words. After
  `Begun`, the byte `1` states that the program did not hand back
  every `rotating` secret the server asked for at a loop's end; the
  error names the secret and carries no value, and the finish
  follows it. A value the program did not hand back is not written
  anywhere by the server.
- **A finish with nothing.** A response finish that no response
  precedes states that the server could not read the request.
