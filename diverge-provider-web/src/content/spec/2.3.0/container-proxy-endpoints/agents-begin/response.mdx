```text
[0][dependencies JSON …]    begun: the container holds its arguments, and these are its dependencies
[1][error JSON …]    not begun: the connection had begun, or the arguments were refused
[2][chunk JSON …]    one chunk of the conversation
[3]                  active: a loop began
[4]                  inactive: that loop ended
```

- **The sequence.** Exactly one response whose first byte is `0`,
  followed by zero or more loops, followed by the response finish
  when the server ends; or exactly one response whose first byte is
  `1`, followed by the response finish. A loop is exactly one
  response whose payload is the byte `3` and nothing else, followed
  by zero or more responses whose first byte is `2`, in the order the
  container produced them, followed by exactly one response whose
  payload is the byte `4` and nothing else. The server sends no
  response whose first byte is `2`, `3` or `4` before `Begun`, none
  whose first byte is `2` outside a loop, and none after the finish.
- **Active and inactive.** The server sends the byte `3` when the
  agent's server answers the loop's `POST /run` with `2xx`, before
  the first chunk of that loop, and the byte `4` when the event
  stream of that answer ends, after the last chunk of that loop,
  whether the stream ended cleanly or by failing. The server
  produces both itself and relays neither from the agent's server:
  every event of the agent's server is sent under the byte `2`, so
  no event is read as either. Neither carries bytes after the first.
  The server sends no byte `3` while a loop is open, and no byte `4`
  while none is.
- **The dependencies.** The bytes after the byte `0` are a JSON
  array of the dependency tool templates the container's program
  answered its registration with, each as the
  [dependencies](/endpoints/containers-agents-run/server/dependencies/)
  channel of the run defines one, in the order the program declared
  them; empty when the program declared none. The server sends the
  array exactly as the program produced it.
- **The chunk.** The bytes after the byte `2` are one chunk as the
  [containers::agents::run response](/endpoints/containers-agents-run/response/)
  defines it, as JSON, which the server sends as the agent's server
  produced it. The first chunks of a loop are the
  user parts of the message it started on — one chunk per content
  block, each carrying the message's `key` — or of every message it
  started on, in the order sent.
- **`_meta`.** The server sets nothing under `_meta`. Every member of
  `_meta`, and every other member of the chunk, is sent as the
  agent's server produced it.
- **The error.** After the byte `1`, exactly one JSON value in the
  form defined on the [volumes::list response](/endpoints/volumes-list/response/)
  page. Refused arguments carry the container's own words.
- **A finish with nothing.** A response finish that no response
  precedes states that the server could not read the request.
