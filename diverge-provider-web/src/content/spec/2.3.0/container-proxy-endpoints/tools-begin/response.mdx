summary: 'The server sends Begun once, carrying the secrets the container takes and the permissions it holds, or an error and the finish; after Begun it sends Active whenever an exchange is in flight where none was and Inactive, carrying the rotating secrets, whenever the last in flight is answered, and the finish when the server ends or after the one error it sends when it cannot collect them.'

```text
[0][registration JSON …]    begun: the container holds its arguments, and these are its secrets
[1][error JSON …]           not begun: the connection had begun, or the arguments were refused; or, after begun, the rotating secrets could not be collected
[2]                         active: an exchange is in flight where none was
[3][values JSON …]          inactive: the last exchange in flight was answered, and these are the rotating secrets
```

- **The sequence.** Exactly one response whose first byte is `0`,
  followed by zero or more periods of activity, followed by the
  response finish when the server ends; or exactly one response
  whose first byte is `1`, followed by the response finish. A period
  of activity is exactly one response whose payload is the byte `2`
  and nothing else, followed by exactly one response whose first
  byte is `3`, or, where the server cannot collect the rotating
  secrets, by exactly one response whose first byte is `1` and the
  response finish. The server sends no response whose first byte is
  `2` or `3` before `Begun`, no byte `2` while a period is open, no
  byte `3` while none is, and none after the finish.
- **Active and inactive.** An exchange is one
  [mcp-list-tools](/container-proxy-endpoints/tools-begin/client/mcp-list-tools/),
  [mcp-list-resources](/container-proxy-endpoints/tools-begin/client/mcp-list-resources/),
  [mcp-call-tool](/container-proxy-endpoints/tools-begin/client/mcp-call-tool/) or
  [mcp-read-resource](/container-proxy-endpoints/tools-begin/client/mcp-read-resource/)
  channel, from its request to its answer; an
  [mcp-notifications](/container-proxy-endpoints/tools-begin/client/mcp-notifications/)
  channel is no exchange. The server sends the byte `2` when the
  number of exchanges in flight goes from none to one, before that
  exchange is delivered to the program, and the byte `3` when the
  number goes from one to none, after the last exchange is answered
  and after the program has handed back the rotating secrets. The
  server produces both itself and relays neither from the program.
  The byte `2` carries nothing after it.
- **The registration.** The bytes after the byte `0` are a JSON
  object of two members, each absent when empty: `secrets`, an
  object whose every member is a secret's name, as the container's
  template declares it, to the mode the program takes it in, the
  string `fixed` or `rotating`, in the order the program declared
  them; and `permissions`, an array of grants, in the order the
  program declared them, in the form the
  [registration request](/endpoints/containers-tools-run/server/registration/request/)
  states. A tool container declares no dependencies: a list its
  program answers its registration with is not carried, and the
  object has no `dependencies` member. The server sends the
  declaration and the permissions exactly as the program produced
  them and reads none of them.
- **The values.** The bytes after the byte `3` are a JSON object
  whose every member is the name of a secret the program declared
  `rotating`, to the value the program leaves in it, any JSON value:
  every `rotating` name the program declared, and no other; the
  empty object for a program that declared none `rotating`. The
  server collects them from the program after the last exchange is
  answered, and sends them as the program handed them back. From the
  byte `3` the program holds no values, and the server delivers no
  exchange to a program that declared a secret until the next
  [secrets](/container-proxy-endpoints/tools-begin/client/secrets/)
  channel is answered `Fed`.
- **The error.** After the byte `1`, exactly one JSON value in the
  form defined on the [volumes::list response](/endpoints/volumes-list/response/)
  page. Refused arguments carry the container's own words. After
  `Begun`, the byte `1` states that the program did not hand back
  every `rotating` secret the server asked for at the end of a
  period of activity; the error names the secret and carries no
  value, and the finish follows it. A value the program did not hand
  back is not written anywhere by the server.
- **A finish with nothing.** A response finish that no response
  precedes states that the server could not read the request.
