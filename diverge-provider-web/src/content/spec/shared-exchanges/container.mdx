---
title: 'Container file operations'
summary: "Read, write, and transfer files in a running container — with a write's content travelling on a second channel the provider opens."
order: 3
---

A read streams a file's pieces back until an error or the end. A write
is the inverted one: because only a responder can finish a channel,
the content cannot ride the channel that asked — the provider opens a
second channel back, quoting the caller's write id, and the caller
streams the content into it. A transfer copies a file from one
container into another named by its laboratory id, read on one side
and written on the other without the bytes ever leaving the provider.
