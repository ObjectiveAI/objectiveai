The ask is kind `18` on [`/requests`](/proxy/requests/):

```text
[18][id_len: u16, big-endian][id …][path …]
```

The server answers on `/fuse/stat/{channel}` with exactly one
message — `0` and the nine bytes of a stat — kind and size — `1` for nothing at the path, `2` and a message — then the close. A path closed cleanly with no
message is the operation not served; an abrupt end is the operation
failed, and it is not asked again — see [FUSE](/proxy/fuse/).

- **Missing is empty.** On a file mount, `1` states that the caller holds nothing under the id yet; the file reads as empty, and the first `write` makes it.

The ask is the target of [FUSE](/proxy/fuse/): the mount's id and the entry's path.
