Seven asks carry the operations of the mounts the proxy makes from
[the environment](/proxy/environment/). Every ask names a mount by
its `id` and an entry by its path; every answer is one message.

| Kind | Ask | Payload after the kind | Answered on | With |
|------|-----|------------------------|-------------|------|
| `18` | stat | `[id_len: u16, big-endian][id …][path …]` | [`/fuse/stat/{channel}`](/proxy/fuse/stat/) | `0` and nine bytes, `1` missing, `2` error |
| `12` | read | `[id_len: u16, big-endian][id …][path …]` | [`/fuse/read/{channel}`](/proxy/fuse/read/) | `0` the bytes, `1` missing, `2` error |
| `13` | write | `[id_len: u16, big-endian][id …][path_len: u16, big-endian][path …][bytes …]` | [`/fuse/write/{channel}`](/proxy/fuse/write/) | `0` ok, `1` error |
| `14` | list | `[id_len: u16, big-endian][id …][path …]` | [`/fuse/list/{channel}`](/proxy/fuse/list/) | `0` the entries, `1` missing, `2` error |
| `15` | remove | `[id_len: u16, big-endian][id …][path …]` | [`/fuse/remove/{channel}`](/proxy/fuse/remove/) | `0` ok, `1` error |
| `16` | rename | `[id_len: u16, big-endian][id …][from_len: u16, big-endian][from …][to …]` | [`/fuse/rename/{channel}`](/proxy/fuse/rename/) | `0` ok, `1` error |
| `17` | mkdir | `[id_len: u16, big-endian][id …][path …]` | [`/fuse/mkdir/{channel}`](/proxy/fuse/mkdir/) | `0` ok, `1` error |

- **The id.** The `id` of a mount named in the environment, UTF-8,
  echoed on every ask for that mount.
- **The path.** The entry's path relative to the mount's root:
  `/`-separated UTF-8 with no leading `/`, no empty component, and no
  `.` or `..` component; empty for a file mount and for a directory
  mount's root. Where a path is the last field it runs to the end of
  the payload; where bytes or a second path follow it, its length
  precedes it.
- **A file mount asks three.** For a mount named under `files`, the
  proxy asks only `stat`, `read` and `write`, each with the empty
  path. For a mount named under `directories`, it asks all seven,
  with the entry's path.
- **A read-only mount asks no mutation.** For a mount named
  `readonly`, the proxy asks no `write`, `remove`, `rename` or
  `mkdir`.
- **One message, then the close.** Every answer is exactly one
  message — the frame its page shows — then the close. A path closed
  cleanly with no message is the operation not served.
- **Nothing is repeated.** An operation whose path ended abruptly, or
  whose `/requests` connection ended before the path was opened, is
  reported inside the container as failed and is not asked again.
- **A file is one message.** A `read` answers a file whole and a
  `write` carries it whole; neither is paged or chunked.
