The ask is kind `17` on [`/requests`](/proxy/requests/):

```text
[17][id_len: u16, big-endian][id …][path …]
```

The server answers on `/fuse/mkdir/{channel}` with exactly one
message — `0` ok, `1` and a message — then the close. A path closed cleanly with no
message is the operation not served; an abrupt end is the operation
failed, and it is not asked again — see [FUSE](/proxy/fuse/).

- **Under an existing directory.** The path is not empty, and its parent is a directory the caller holds.

The ask is the target of [FUSE](/proxy/fuse/): the mount's id and the entry's path.

The answer is the ack of [FUSE](/proxy/fuse/).
